# النسخ الاحتياطي اليدوي والاسترجاع

## ما الذي يحميه كل مكان (حدود صريحة)
| المكان | يحوي | لا يحوي |
|---|---|---|
| **GitHub** | الكود، ملفات SQL (المخطط، RLS، الدوال)، الوثائق | **لا بيانات**: لا طلبات ولا زبائن ولا حسابات موظفين ولا صور المنتجات |
| **قاعدة Supabase** | الطلبات، الزبائن، المنتجات، الكوبونات، المرتجعات، سجل التدقيق، حسابات الموظفين (`auth`) | ملفات الصور نفسها (فقط بياناتها الوصفية) |
| **Supabase Storage** | صور المنتجات | لا شيء من القاعدة |
النسخ اليدوي = لقطة لحظية. لا استرجاع إلى لحظة معينة (PITR) ولا نسخ تلقائي هنا. ما تتيحه خطتك من نسخ تلقائي **تحقق منه** في Database → Backups، ولا تعتمد عليه وحده.

## القواعد
- النسخ تحوي بيانات زبائن: **خارج GitHub دائماً** (`backups/` و`*.dump` في `.gitignore`)، على قرص مشفّر أو مجلد خاص، ولا ترسلها بالبريد.
- **مفتاح `service_role` وكلمة سر القاعدة**: في جلسة الطرفية فقط أثناء التنفيذ، ثم أغلقها. ليسا في المشروع ولا في Netlify ولا في GitHub.
- احتفظ بثلاث نسخ على الأقل بتواريخ مختلفة، وجرّب الاسترجاع مرة كل فترة (نسخة لم تُجرَّب ليست نسخة).
- قبل أي ترحيل SQL (مثل 10 و11) خذ نسخة كاملة أولاً.

## 1) نسخ قاعدة البيانات
المتطلبات: [Supabase CLI](https://supabase.com/docs/guides/cli) (أو `pg_dump`) ورابط الاتصال من Project Settings → Database (Connection string، مع كلمة سر القاعدة).
```powershell
$env:DB_URL = "postgresql://postgres:كلمة-السر@db.xxxx.supabase.co:5432/postgres"
$d = "backups\$(Get-Date -Format yyyy-MM-dd_HHmm)"; New-Item -ItemType Directory $d | Out-Null
supabase db dump --db-url $env:DB_URL -f "$d\schema.sql"                 # المخطط + RLS + الدوال (public)
supabase db dump --db-url $env:DB_URL --data-only -f "$d\data.sql"       # بيانات public
supabase db dump --db-url $env:DB_URL --data-only --schema auth -f "$d\auth-data.sql"   # حسابات الموظفين (users + mfa)
Remove-Item Env:\DB_URL
```
- بدائل: `pg_dump "$DB_URL" -Fc -f full.dump`. خيارات `supabase db dump` تتغير بين الإصدارات: راجع `supabase db dump --help`.
- حسابات الموظفين في `auth`: إن لم تحفظها فسيُعاد دعوة الموظفين بعد الاسترجاع ثم `register_staff_by_email` (أبسط وأقل خطراً). احفظ أيضاً **قائمة الموظفين وأدوارهم** (من /admin → الموظفون).
- لقطة قياس قبل النسخ: شغّل الجزء الأول من `scripts/verify_backup.sql` على المصدر ودوّن الأرقام.

## 2) نسخ صور المنتجات
على جهازك فقط:
```powershell
$env:SUPABASE_URL = "https://xxxx.supabase.co"; $env:SUPABASE_SERVICE_ROLE_KEY = "...";
node scripts/backup-storage.mjs
Remove-Item Env:\SUPABASE_SERVICE_ROLE_KEY
```
ينتج `backups/<وقت>/storage/` و`storage-manifest.json` (حجم وبصمة SHA-256 لكل ملف). **السكربت لم يُشغَّل على مشروع حقيقي**؛ جرّبه وتأكد أن عدد الملفات يطابق لوحة Storage.

## 3) نسخ ملفات المشروع
المخطط والسياسات والدوال موجودة أصلاً في `supabase/*.sql` (مصدر الحقيقة) وفي GitHub. ما عدّلته يدوياً في لوحة Supabase دون ملف SQL (إعدادات Auth، قالب بريد الدعوة، أسرار الـ Edge Function) **دوّنه** في ملف خاص خارج المستودع.

## 4) الاسترجاع إلى بيئة اختبار (لا تبدأ بالإنتاج)
1. أنشئ مشروع Supabase **جديداً فارغاً** للاختبار.
2. اختر مساراً:
   - **أ) إعادة بناء + بيانات (الأوضح):** نفّذ `supabase/01…11` بالترتيب (انظر `05-DEPLOY.md`) ثم `psql "$TEST_DB_URL" -f data.sql`. (إن واجهت أخطاء قيود بسبب الترتيب: `SET session_replication_role = replica;` قبل الاستيراد في الجلسة نفسها، ثم أعدها.)
   - **ب) استرجاع المخطط من النسخة:** `psql "$TEST_DB_URL" -f schema.sql` ثم `data.sql`.
3. الصور: أنشئ الحاوية `product-images` (من `02_rls_storage.sql`) وارفع محتويات `storage/` بالمسارات نفسها (من لوحة Storage، أو سكربت رفع بمفتاح الاختبار). مسارات الصور مخزّنة في `product_images.path`.
4. الموظفون: استورد `auth-data.sql` إن حفظته، وإلا أعد دعوة الموظفين.
5. **التحقق من السلامة:** شغّل `scripts/verify_backup.sql` على مشروع الاختبار:
   - الأعداد والمجاميع تطابق ما دوّنته من المصدر.
   - قوائم «Integrity» **فارغة**، و«table without RLS» **فارغة**، وعدد السياسات والدوال مطابق للمصدر.
   - افتح موقعاً مربوطاً بمشروع الاختبار: منتج بصورة ظاهرة، تسجيل دخول المدير، طلب تجريبي، تقرير.
6. سجّل تاريخ التجربة والنتيجة. أي خلل = النسخة غير صالحة؛ أصلح الإجراء قبل الاعتماد عليه.

## 5) الاسترجاع في الإنتاج (كارثة فقط)
قرارات بشرية لا تُؤتمت: أوقف المتجر (صفحة صيانة)، خذ نسخة من الحالة الحالية حتى لو تالفة، استرجع على مشروع **جديد** وتحقق (الخطوة 4)، ثم بدّل `VITE_SUPABASE_URL/ANON_KEY` في Netlify وأعد النشر. لا تكتب فوق مشروع حي.
