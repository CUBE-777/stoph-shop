## اختبار التزامن اليدوي (توفر المنتج أثناء الطلب)
التصميم: `_price_order` يقفل صف المنتج والمتغير بـ `FOR SHARE` طوال معاملة الطلب، وتعديل التوفر (UPDATE) ينتظر انتهاءها، فلا يُقبل طلب على متغير صار غير متاح بعد التحقق. **هذا استنتاج من قراءة الكود لا نتيجة اختبار.**
الإجراء (نافذتا SQL Editor على مشروع تطوير، منتج/متغير تجريبي):
1. نافذة A: `begin; select public.create_order(...المتغير X...);` (لا تُنهِ المعاملة).
2. نافذة B: `update public.product_variants set is_available = false where id = 'X';` → **يجب أن تتعلّق** (تنتظر).
3. نافذة A: `commit;` → تكتمل B بعدها. الطلب صحيح (سبق الإلغاء).
4. اعكس: نافذة B أولاً `begin; update ... set is_available=false;` ثم A: `select create_order(...)` → **تتعلّق**، ثم عند `commit` في B تفشل A بـ `variant_unavailable`.
سجّل ما حدث؛ إن لم يتطابق فهو خلل يجب إصلاحه قبل الإطلاق.
