# المشكلات المتبقية، الخدمات المدفوعة، وقرار SEO

## ما يحتاج تدخلك قبل الإطلاق (مرتب بالأهمية)
1. **تشغيل SQL والاختبارات** (ملفات 10-11 وdb_tests_phase3 لم تُنفَّذ قط). أصلح أي خطأ أولاً.
2. `npm install` → ارفع `package-lock.json` → `npm audit` → `npm run build` (F11).
3. خطة Supabase مناسبة: المجانية تتوقف بعد أسبوع خمول (F16).
4. قائمة الضبط اليدوي (`01-SECURITY-REVIEW.md` §3) وتعطيل التسجيل الذاتي.
5. تفعيل MFA بالترتيب الآمن (`02-MFA.md`) واختبار الاسترجاع على حساب تجريبي.
6. تجربة استرجاع نسخة احتياطية على مشروع اختبار (`03-BACKUP-RESTORE.md`).
7. تجربة CSP ثم تفعيلها (`05-DEPLOY.md` د-4).
8. تجربة بصرية: RTL/LTR، هاتف/كمبيوتر، داكن/فاتح، لوحة المفاتيح فقط (Tab/Enter) على: الرئيسية، منتج، السلة، الطلب، التتبع، لوحة الإدارة. الفحص الآلي غطّى التباين فقط.

## قرارات مفتوحة / قيود معروفة
- الكوبون المستهلك لا يُعاد عند إلغاء الطلب (F14).
- لا CAPTCHA؛ التحديد حسب IP/الهاتف بأفضل جهد (F13).
- لا تكلفة شراء ولا مصاريف في النظام ⇒ **لا ربح صافٍ** (مقصود ومذكور في التقارير).
- توفر المنتج منطقي (متوفر/غير متوفر)، لا كميات مخزون.
- مرتجع جزئي (بعض أصناف الطلب) غير مدعوم: الإرجاع على مستوى الطلب كله.
- لا استرداد مالي مسجّل (الدفع عند الاستلام).
- مطابقة المدن العربية تتطلب صفاً لكل تهجئة.
- `audit_logs` تحوي بيانات شخصية: سياسة احتفاظ وامتثال قانوني (F15).
- أرشيف المشروع الذي تسلّمته لم يحوِ `package-lock.json` ولا `.gitignore` ولا `.env.example` (أُضيف الأخيران).

## ميزات تتطلب خدمات مدفوعة (لم أفعّل أيّاً منها)
| الميزة | التكلفة/الشرط |
|---|---|
| Phone/SMS MFA | إضافة مدفوعة في Supabase (≈ 75$/شهر للمشروع الأول) — **غير لازمة**: TOTP مجاني |
| تحويل الصور في Storage (تغيير الحجم على الخادم) | غير متاح في الخطة المجانية؛ **استُعيض عنه** بضغط الصور في المتصفح قبل الرفع (مجاني) |
| نسخ يومية تلقائية / PITR | حسب الخطة المدفوعة؛ تحقق من لوحتك |
| تعطّل المشروع المجاني بالخمول | يتطلب خطة مدفوعة لمتجر حقيقي |
| CAPTCHA (Turnstile) | مجاني عند Cloudflare لكنه يحتاج حساباً وإعداداً |
| خدمة prerender للمشاركة الاجتماعية | غالباً مدفوعة (انظر أدناه) |

## SEO: ماذا فعلت وماذا أقترح (دون تغيير البنية)
**نُفّذ (بلا تغيير بنية):** عنوان ووصف وcanonical وOpen Graph لكل صفحة (بعد تحميل JS)، JSON-LD `Product` في صفحة المنتج، وسوم ثابتة افتراضية في `index.html`، `robots.txt` (يمنع الإدارة والسلة والدفع والتتبع)، سكربت `sitemap`، وصور بأبعاد وتحميل كسول.

**القيد الحقيقي:** الموقع تطبيق SPA. Google يشغّل JavaScript فيقرأ ما سبق، لكن **معاينات واتساب/فيسبوك/تيليغرام لا تشغّل JS** فتظهر وسوم `index.html` العامة لكل الروابط (عنوان المتجر لا اسم المنتج وصورته). وفهرسة Google للـ SPA أبطأ وأقل ضماناً من HTML جاهز.

| الخيار | الفائدة | التكلفة/المخاطر |
|---|---|---|
| **أ) الإبقاء كما هو (الحالي)** | لا مخاطر، لا تكلفة | معاينات اجتماعية عامة؛ فهرسة أبطأ |
| ب) Prerender وقت البناء لصفحات المنتجات (سكربت يولّد HTML ثابتاً لكل منتج) | معاينات ووسوم صحيحة، بلا تغيير إطار | منتج جديد يحتاج إعادة بناء/نشر (يمكن Webhook)؛ تعقيد بناء؛ يحتاج اختباراً |
| ج) Netlify Edge Function تحقن وسوم OG للزواحف فقط | حل المعاينات دون إعادة بناء | كود edge يستعلم Supabase؛ صيانة؛ مخاطر أخطاء إنتاج |
| د) الانتقال إلى Next.js/Astro | SSR/SSG كامل | **إعادة كتابة كبيرة**، خطر كسر RTL/الفرنسية والإدارة والاختبارات، تكلفة وقت عالية |
**توصيتي:** ابقَ على (أ) عند الإطلاق، وقِس: إن كانت المشاركة عبر واتساب قناة بيع رئيسية فنفّذ (ج) أو (ب) لاحقاً. لا أنصح بـ (د) لمجرد SEO. لم أنفّذ أي تغيير بنية.
