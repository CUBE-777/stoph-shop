# Stoph Shop — المرحلة 1 (MVP)

متجر مغربي: React + Vite + Supabase (قاعدة البيانات، المصادقة، تخزين الصور) + Netlify.
الدفع عند الاستلام فقط. عربي (RTL) وفرنسي (LTR)، وضع داكن افتراضي.

## ما تم اختباره فعلاً وما لم يُختبر

**اختُبر فعلاً (في بيئة البناء):**
- `npm test`: 8 اختبارات للمنطق المشترك في `src/lib/shop.js` (تطبيع الهاتف، الأسعار والخصم، قواعد التوفر، التحقق من النموذج، السلة، رسوم التوصيل، انتقالات حالة الطلب) — **نجحت كلها**.
- فحص صياغة (syntax) كل ملفات JS/JSX عبر TypeScript — دون أخطاء.
- تطابق مفاتيح الترجمة بين العربية والفرنسية (209 مفتاحاً في كل لغة).

**لم يُختبر (لأن البيئة بلا إنترنت ولا PostgreSQL):**
- `npm install` و`npm run build` و`npm run dev`: لم تُشغَّل، فقد يظهر خطأ بسيط عند أول تشغيل.
- ملفات SQL لم تُنفَّذ على قاعدة بيانات حقيقية. اختبارات قاعدة البيانات جاهزة في `tests/db/db_tests.sql` ويجب تشغيلها يدوياً (انظر الخطوة 7).
- الاتصال بـ Supabase، رفع الصور، تسجيل دخول المدير، النشر على Netlify: يحتاجون إعدادك أنت.
- لم يُراجَع الشكل البصري على متصفح أو هاتف.

## 1) إعداد Supabase
1. أنشئ مشروعاً جديداً في supabase.com (اختر منطقة قريبة، مثل أوروبا).
2. افتح **SQL Editor** ونفّذ الملفات بهذا الترتيب (كل ملف كاملاً):
   `supabase/01_schema.sql` ← `02_rls_storage.sql` ← `03_functions.sql`
3. من **Project Settings → API** انسخ: `Project URL` و`anon public key`.
   لا تستخدم مفتاح `service_role` في هذا المشروع إطلاقاً.

## 2) أول مدير (آمن، دون كلمة مرور في الكود)
1. **Authentication → Users → Add user → Create new user**: بريدك وكلمة مرور قوية تختارها أنت.
2. **Authentication → Sign In / Providers**: عطّل **Allow new users to sign up**.
3. افتح `supabase/04_first_admin.sql`، بدّل `CHANGE-ME@example.com` ببريدك، ونفّذه مرة واحدة.
   الدالة ترفض العمل إذا وُجد مالك سابق، ولا يمكن استدعاؤها من المتصفح.

حتى لو سُجّل مستخدم غريب، لن يملك صلاحيات: كل سياسات RLS تتحقق من `staff_profiles` والأدوار.

## 3) التشغيل المحلي (VS Code + PowerShell)
```powershell
cd stoph-shop
npm install
Copy-Item .env.example .env.local
# عدّل .env.local وضع VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
npm run dev
```
المتجر: http://localhost:5173 — الإدارة: http://localhost:5173/admin

## 4) النشر على Netlify
1. ادفع المشروع إلى GitHub (`.env.local` مستثنى تلقائياً عبر `.gitignore`).
2. Netlify → **Add new site → Import from Git** (الإعدادات تُقرأ من `netlify.toml`).
3. **Site configuration → Environment variables**: أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`
   (واختيارياً `VITE_CONTACT_PHONE` و`VITE_CONTACT_WHATSAPP` و`VITE_CONTACT_EMAIL` و`VITE_LOGO_URL`).
4. أعد النشر. في Supabase: **Authentication → URL Configuration** أضف رابط موقعك.

## 5) قبل الإطلاق (مهم)
- من `/admin/shipping` عدّل **السعر الافتراضي**: القيمة 40 درهماً مجرد قيمة مؤقتة وضعتُها أنا.
- نصوص صفحة التوصيل والسياسات مسودة عامة؛ سياسة الإرجاع غير مكتوبة بعد. راجعها قانونياً.
- أضف تصنيفاتك ومنتجاتك وصورك الحقيقية من `/admin`.

## 6) بيانات تجريبية (اختيارية، للتطوير فقط)
نفّذ `supabase/05_seed_demo_optional.sql`. كل صفوفها تبدأ بـ `demo-` ويوجد سطر حذف في آخر الملف.

## 7) الاختبارات
- منطق الواجهة: `npm test`.
- قاعدة البيانات: الصق `tests/db/db_tests.sql` في SQL Editor ونفّذه على مشروع تطوير. يعمل داخل معاملة تنتهي بـ `ROLLBACK`
  (لا يترك شيئاً)، ويفحص: حساب الأسعار والخصم والتوصيل على الخادم، لقطة الطلب، رفض المتغير/المنتج غير المتاح أو المخفي،
  رفض الكمية والهاتف غير الصحيحين، عدم إنشاء طلبات جزئية، ومنع الزائر والمستخدم غير الموظف من قراءة الطلبات أو تغيير حالتها.
  رسالة النجاح: `ALL DB TESTS PASSED`.

## بنية المشروع
```
supabase/   ملفات SQL (جداول، RLS، دوال create_order / set_order_status، أول مدير، بيانات تجريبية)
src/lib/    shop.js (منطق خالص مُختبَر)، supabase.js، hooks.js
src/services/  catalog.js (المتجر) و admin.js (الإدارة): كل عمليات قاعدة البيانات هنا فقط
src/context/   اللغة/المظهر، السلة
src/pages/, src/components/, src/admin/   الواجهات
src/i18n/dictionary.js   كل النصوص بالعربية والفرنسية
src/styles.css   كل الألوان والمسافات كمتغيرات CSS
```
استبدال الشعار: عدّل مكوّن `Logo` في `src/components/ui.jsx` أو اضبط `VITE_LOGO_URL`.

## قرارات وحدود معروفة
- **الأمان:** الطلب يُنشأ فقط عبر `create_order` (يحسب الأسعار والتوصيل ويتحقق من التوفر ذرّياً). المتصفح لا يرسل أي سعر.
  الزائر لا يملك أي صلاحية على الطلبات والزبائن. تغيير الحالة فقط عبر `set_order_status` بانتقالات محددة.
- **لا حماية من الإغراق (spam):** أي شخص يستطيع استدعاء `create_order`. أضف لاحقاً CAPTCHA أو Edge Function مع تحديد معدل.
- **جدول الزبائن:** يُحدَّث الاسم عند تكرار نفس رقم الهاتف؛ الطلب نفسه يحفظ لقطة ثابتة لا تتأثر.
- **حفظ المنتج في الإدارة:** المنتج والمتغيرات والصور تُحفظ بطلبات متتالية وليست معاملة واحدة؛ عند فشل خطوة تبقى السابقة محفوظة وتظهر رسالة خطأ.
- **لم أنفّذ** لوحة جانبية للسلة (صفحة السلة تكفي للـ MVP)، ولا نموذج رسائل في صفحة التواصل (لا يوجد خادم لاستقباله؛ تُعرض بيانات التواصل من متغيرات البيئة).
- الأدوار والصلاحيات موجودة في قاعدة البيانات (`owner`, `manager`) وتُطبَّق على كل شاشة، لكن واجهة إدارة الموظفين مؤجلة للمرحلة 2.
- لم أبدأ المرحلة الثانية، كما طلبت.
